**Severity:** friction

**Author:** Joe-Degler
**Context:** Bounded continuation reassessment recorded in [Plan A Progress](../plans/feat-0044-cross-agent-portability/PLAN-FEAT-0044A-codex-runtime-contract-verification.md#progress).

These compound readiness issues remain after M1 registrar and M2 deletion closure:

- Global init creates dedup flags at `src/commands/init.ts:184` before Codex registration at line 218 can fail. `src/commands/init-entrypoint.ts:32-35` suppresses project invocation based on flag existence, even when the global command is untrusted or disabled; a flag does not establish that the global command will run.
- Global init and uninstall hardcode `HOME/.codex` (`src/commands/init.ts:218`, `src/commands/uninstall.ts:371`), ignoring `CODEX_HOME`. Official [advanced configuration documentation](https://learn.chatgpt.com/docs/config-file/config-advanced#config-and-state-locations), checked 2026-09-07, confirms that Codex uses `CODEX_HOME`, defaulting to `~/.codex`.
- Claude's global command builder, `globalEntrypointCommand` in `src/commands/init.ts`, still emits an unquoted absolute launcher path. Raw paths requiring shell quoting can fail to execute. M1 preserves exact scope-derived commands for idempotent registration and removal; it intentionally does not change command transport. The limitation is documented in [Bash Entrypoint](../domain/bash-entrypoint.md#hook-registration). A later bounded quoting migration needs regression coverage for registration/removal compatibility and shell smoke coverage for paths requiring quoting. This does not require a runtime authorization redesign.
- A proposed adapter policy that checks only final output misses unsupported results overwritten during sequential reduction (`src/engine/execute.ts:605-709`). Capability handling needs to account for individual results before reduction; new turn-state recording and handoff transformations also need an adapter semantics audit.
