# Measure Isolated E2E Workers and Share Docker Builds

This ExecPlan is a living document maintained under `docs/plans/PLANS.md`. Keep Product Context, Progress, Surprises & Discoveries, Decision Log, Outcomes & Retrospective, and Related Domain Knowledge Documents current.

**Originating Feature:** None; standalone user-approved test speed/reliability task #1. Author: Joe-Degler.

## Purpose / Big Picture

Make full validation faster and more reliable without reducing what it checks. First prove an optional runner that distributes E2E files across isolated Docker containers; only after measured results and review GO should the commit gates adopt shared-build orchestration. Coverage remains unsharded with unchanged 95% line/function thresholds, exclusions, assertions and timeout limits.

## Product Context

Developers currently wait for long, variable E2E runs and duplicate coverage/E2E image builds. This work affects local validation time, resource contention and confidence that every requested test actually ran, not Clooks runtime behavior. Success means complete passing suites, truthful failures and useful timings, with one image build per combined gate. No product behavior, native-agent workflow, global settings, dependencies or coverage policy changes are intended.

## Context and Orientation

E2E means end-to-end tests: `test/e2e/*.e2e.test.ts` invoke the compiled Clooks binary through `test/e2e/helpers/sandbox.ts`, exercising startup, configuration, hook execution and JSON output. `test/Dockerfile` supplies Bun, dependencies and a non-root test user; `test/docker-entrypoint.sh` typechecks and compiles read-only mounted inputs before running tests. The Docker marker prevents accidental host execution. Non-root execution is necessary for permission tests.

`package.json` exposes `test:e2e`, `test:e2e:build` and `test:e2e:run`. The last is the direct argument-passthrough interface; `./test/e2e/...` denotes an explicit path whereas bare `test/e2e/...` can be interpreted as a name filter under bunfig's unit root and select zero tests. `lefthook.yml` currently runs coverage and E2E hooks in parallel, each building/tagging `clooks-e2e`. `bunfig.toml` owns the engine coverage ratchet; `hookcoverage.toml` is the separate report-only hook-pack configuration. `test/e2e/validation-config.e2e.test.ts` checks script/config wiring and failure propagation.

An immutable image ID identifies the exact image returned by one build, independent of later changes to a shared tag. A worker here is a disposable Docker container assigned complete E2E files, not concurrent tests in a shared Bun process. A selection manifest is the exact list of selected files plus their unique worker assignments; it proves scheduling completeness, not passing execution by itself.
